# High-Fidelity Creative Execution Workflow

## Trigger

Use this workflow for creator-facing work where the expected standard is exceptional rather than merely competent: screenplay pages, major revisions, character architecture, mythology, pitch materials, studio bibles, producer packages, or cross-repository canon changes.

## Phase 1 — Resolve

1. Resolve the project and authoritative repository.
2. Load the project manifest, current canon, decision ledger, relevant artifact, and creator taste profile.
3. Reconstruct the request into an Intent Contract.
4. Select light, standard, or deep Creative Council mode.
5. Declare assumptions and identify any blocking uncertainty.

## Phase 2 — Diagnose

Before writing, produce a private diagnostic map:

- current artifact function;
- strongest existing material to protect;
- primary failure or opportunity;
- audience information path;
- character causal chain;
- production implications;
- downstream dependency risks;
- likely cliché or model-default traps.

Do not draft until the diagnosis identifies what the new version must do differently.

## Phase 3 — Generate

The Artifact Specialist creates one coherent primary version.

Generation rules:

- write from canon and the Intent Contract;
- preserve successful material unless change is necessary;
- make behaviour causal and actor-playable;
- control audience knowledge deliberately;
- prefer concrete dramatic action over explanation;
- preserve project-specific tone over generic prestige;
- mark new invention, inference, and open questions;
- stay within production and format constraints.

## Phase 4 — Council review

Run only applicable passes:

- Intent Custodian;
- Canon Editor;
- Story Architect;
- Character Psychologist;
- Audience Simulator;
- Human Writing Editor;
- Producer Pass;
- Continuity Editor;
- Adversarial Critic.

Each pass returns bounded findings, not a replacement draft.

## Phase 5 — Targeted repair

1. Rank findings by impact on the Intent Contract.
2. Reject taste drift, generic polishing, and low-value changes.
3. Repair only the affected sections.
4. Preserve successful language and structure.
5. Repeat validation once when blocking failures remain.
6. Escalate unresolved contradictions rather than hiding them.

## Phase 6 — Evaluate

Run the Wow Readiness Scorecard.

The execution record must include:

- dimension scores with evidence;
- confidence by dimension;
- assumptions;
- unresolved uncertainty;
- changes made after critique;
- findings rejected and why;
- canon conflicts;
- synchronization requirements;
- approval status.

## Phase 7 — Present

The creator receives:

1. the finished artifact first;
2. a concise statement of what materially improved;
3. only the decisions or uncertainties requiring attention;
4. repository synchronization plan;
5. approval controls.

Do not bury the artifact beneath process narration.

## Phase 8 — Learn

After creator review:

- record accepted decisions;
- record corrections and rejection reasons;
- update project canon only through approval;
- update the creator taste profile only when evidence is durable;
- store the execution as a benchmark when it materially represents the creator's standard;
- propagate approved changes through dependent files.

## Success condition

The workflow succeeds when the creator spends their attention judging creative choices rather than re-explaining context, correcting generic assumptions, or repairing avoidable continuity errors.
