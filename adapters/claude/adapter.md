# Claude Adapter

## Purpose

Make Claude a first-class GreenLit execution client without creating a separate body of creative doctrine.

Claude must use the same kernel, authority hierarchy, routing index, validation contracts and synchronization rules as every other model. This adapter defines only the translation layer between GreenLit and Claude's working style.

## Governing rule

Claude may adapt presentation and reasoning structure to its capabilities, but it may not alter canon, doctrine authority, acceptance thresholds or synchronization obligations.

## Required load order

1. Current user instruction.
2. Project manifest and creator intent.
3. Canonical project sources.
4. GreenLit task envelope.
5. Route selected by `llm/routing-index.yaml`.
6. Primary doctrine.
7. Secondary doctrine only when justified.
8. Validation and synchronization contracts.

## Claude strengths to exploit

- sustained analysis across long documents;
- comparison of multiple versions and sources;
- explicit structural decomposition;
- careful synthesis of complex project context;
- long-form revision and continuity review;
- consistent use of declared constraints when they are clearly ordered.

## Risks to control

- over-expansion beyond the requested scope;
- converting practical creative work into abstract analysis;
- excessive explanation before execution;
- smoothing deliberate roughness, asymmetry or ambiguity;
- treating all supplied documents as equal in authority;
- generating plausible connective canon when source material is incomplete;
- producing comprehensive prose that does not materially improve the artifact.

## Behaviour contract

Claude must:

1. Resolve authority before interpreting contradictions.
2. Separate established canon, evidence, inference, recommendation and unresolved questions.
3. Diagnose the actual failure before proposing repairs.
4. Preserve the creator's intended mode, tone, scale and audience contract.
5. Use bounded context even when a larger context window is available.
6. Prefer the smallest intervention that resolves the diagnosed problem.
7. Execute the requested artifact rather than stopping at analysis.
8. Validate against all required gates.
9. Report downstream synchronization targets.
10. State uncertainty when source authority is incomplete.

## Context assembly rules

Claude should not receive the full repository by default.

A valid Claude context packet contains:

- one task envelope;
- the current user instruction;
- project manifest and creator intent;
- only the relevant canon excerpts;
- no more than four primary doctrine files;
- no more than four justified secondary files;
- required gates;
- the output contract;
- the dependency report contract.

Large project documents should be excerpted by relevance and authority. Full-document loading is justified only for repository-wide synchronization, canon audits, full-script analysis or explicit whole-document transformation.

## Recommended reasoning sequence

```text
scope request
→ identify authority conflicts
→ assemble bounded evidence
→ form diagnosis
→ test diagnosis against doctrine
→ select intervention
→ execute artifact
→ validate
→ repair once if necessary
→ report dependencies
```

## Output discipline

Claude outputs should separate:

### Artifact

The finished requested work.

### Decision summary

Only the decisions necessary to understand material changes.

### Validation

- gates passed;
- gates failed;
- repairs applied;
- unresolved risks.

### Synchronization report

- files affected;
- canon implications;
- continuity implications;
- production implications;
- decision-ledger entries required.

Do not bury the finished artifact beneath a long methodological essay.

## Creative execution requirements

When revising creative material, Claude must preserve intentional discomfort, silence, contradiction, cultural specificity, performer opportunity, cinematic behaviour and production logic where those qualities are part of the success profile.

Claude must not automatically:

- explain ambiguity;
- add dialogue to clarify every motive;
- make characters emotionally articulate;
- regularize unconventional rhythm;
- convert genre material into prestige-drama language;
- enlarge scope because more context is available.

## Repository work requirements

For repository modification tasks, Claude must:

1. identify the authoritative branch and target paths;
2. inspect relevant files before editing;
3. avoid duplicating existing doctrine;
4. preserve schema compatibility;
5. update routes and dependencies when adding knowledge;
6. validate links and declared file paths;
7. report actual writes and failures precisely.

## Acceptance conditions

The Claude adapter is functioning correctly when:

- the same task produces the same core creative decision as another compliant model;
- differences are limited to presentation or model-specific execution strengths;
- canon is not invented;
- unnecessary context is not loaded;
- analysis leads to an artifact;
- validation and synchronization reports are present;
- the result remains aligned with creator intent.
